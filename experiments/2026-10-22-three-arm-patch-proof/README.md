# 用三臂证明和回归检查验收 AI 补丁

## 目的

Trail of Bits 在 [Your AI agent fixed the bug, but what else did it change?](https://blog.trailofbits.com/2026/10/21/your-ai-agent-fixed-the-bug-but-what-else-did-it-change/) 中发布了 `patching-bugs` 和 `regression-hunt` 两个插件，核心是两条验收标准：

- **三臂证明**：在原代码上复现检查应失败 → 打补丁后应通过 → 撤回补丁后应再次失败。它证明「是这个补丁修好了 bug」，而不是检查本身写错或碰巧通过
- **回归检查**：补丁不应破坏原本正常、受支持的行为

本实验用一个极小的例子演示：为什么只有三臂证明还不够。

注意：这里的函数、补丁和测试都是本实验自行编写的简化示例，不是 Trail of Bits 插件的实现。

## 步骤

1. `parse_amount()` 原版不支持千位分隔符，bug 报告是 `"1,234.50"` 解析失败
2. 两个候选补丁：
   - 补丁 A：用正则校验格式，修好了千位分隔符，但正则漏了负号
   - 补丁 B：同样的思路，保留可选负号
3. 对每个补丁执行三臂证明，再用 5 个既有用例（含 `"-3"`）做回归检查：原版通过、补丁后失败的即为回归
4. 断言：两个补丁都通过三臂证明；A 有且只有 `-3` 这一个回归；B 没有回归

运行：

```bash
python main.py
```

程序最后输出 `RESULT: ...`，任一检查失败时以非零状态退出。

## 预期结果

- 补丁 A：三臂证明成立，回归 1 个（`-3`），结论「拒绝」
- 补丁 B：三臂证明成立，回归 0 个，结论「可接受」

## 局限与可以继续尝试

- 回归检查只覆盖已有用例，用例没写到的行为照样可能被破坏；Trail of Bits 的做法是追踪改动影响到的真实接口，并在运行中的系统上复现
- 可以把 `ORIGINAL` / `PATCH_*` 换成你自己项目里 Agent 提交的补丁，把 `EXISTING` 换成现有测试，用同样的方式做验收

## 内网复现

- **无需任何第三方依赖**，只用 Python 3.8+ 标准库，无需联网，可直接在内网运行
- 把 `main.py` 拷贝到内网机器执行 `python main.py` 即可
- 若要在内网安装 Trail of Bits 插件本身，需要能访问 GitHub 上的 `trailofbits/skills` 仓库，或先在外网克隆后同步到内网 Git 服务，再按其 README 用本地目录添加插件市场
