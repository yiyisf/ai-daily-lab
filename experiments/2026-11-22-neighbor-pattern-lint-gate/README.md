# 玩具实验：用增量 Diff 静态门禁阻断编码 Agent 照抄邻近不安全代码

## 目的

arXiv 论文 *Coding Agents Propagate Vulnerabilities in Code Bases*（2611.11455）指出：当代码库中存在历史不安全写法时，编码 Agent 会不加区分地把它当成模板复制到新代码里（76.5% 的案例中 Agent 明确归因于「参考了仓库里另一处写法」，尽管 69.9% 的情况下它其实能认出这是漏洞），而且单靠在提示词里强调「注意安全」并不能彻底阻止这种扩散。

对于历史包袱较重的研发仓库，团队往往没法一次性重构所有旧代码，但可以做到**「存量不扩散、增量必拦截」**。本实验**不调用模型、不访问网络**，只用 Python 标准库，实现一个极简的**增量 Unified Diff 静态门禁**：

- 只解析 unified diff 中以 `+` 开头的新增代码行（忽略上下文旧行与删除行）；
- 对新增行检查 5 类高频易被 Agent 照抄的反模式：SQL 字符串拼接、`eval()` 执行、`subprocess(..., shell=True)`、硬编码密钥、以及前端绕过组件库手写 `<div onClick=...>` 伪按钮；
- 验证它在 5 份带历史坏榜样的 PR diff（含 5 处违规新增 + 3 份合规新增）上的拦截率与误报率。

## 步骤

```bash
python main.py
```

无需安装第三方包。程序输出每份 diff 的扫描结果、`METRIC:` 指标、`[PASS]/[FAIL]` 检查项和最终 `RESULT:` 结论；任一检查失败时以非零状态退出。

## 预期结果

- 历史上下文里的旧漏洞写法不会触发误报（便于老仓库渐进落地）
- Agent 在新增行里照抄的 5 类反模式拦截率达 100.0%（5/5）
- 3 份使用参数化查询、安全调用和既有 `<UiButton>` 组件的合规 PR 放行率达 100.0%（3/3）

## 局限

- 本玩具脚本用正则匹配单行新增代码，只演示「增量 Diff 门禁」思路；生产环境应接入 Semgrep、ESLint 自定义规则、Bandit 或 Ruff，并通过 `git diff` 限定只卡新增行
- 跨行语义漏洞仍需要完整的 AST / 数据流分析工具覆盖

## 启示与可以继续尝试

- 与其只在 `AGENTS.md` 里反复写「别抄旧代码」「必须用项目组件库」，不如把高频红线做成 `pre-commit` 或 CI 的增量 Diff 门禁，让编码 Agent 提交前自己跑一遍并按报错修改
- 可以把 `RULES` 扩展成团队自己的前端组件库禁用列表（例如禁止在业务页直接写原生 `<button>` 或绕过设计系统 token）

## 内网复现

- 仅依赖 Python 3 标准库（`re`、`sys`），无任何第三方包，开发机与内网 CI 镜像均可直接运行
- 完全离线运行，不访问外网，不需要 API key 或 GPU
- 若接入真实仓库：将 `DIFF_CASES` 改为读取 `git diff origin/main...HEAD` 标准输入，即可作为本地 Hook 或 CI 检查步骤使用
