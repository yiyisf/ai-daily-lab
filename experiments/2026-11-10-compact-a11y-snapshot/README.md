# 玩具实验：给无视觉模型看页面，原始 HTML 与编号快照差多少

## 目的

LangChain 2026-11-03 的文章比较了 7 套浏览器工具，Stagehand 在 WebVoyager 上以 90% 通过率、1.98 美元总成本领先。文中把原因之一归结为 `snapshot` 返回裁剪过的无障碍树，并给可交互元素编号，Agent 不需要读原始 HTML 或写选择器，截图只作为后备。

团队用的模型没有视觉能力，做 UI 自动化测试时常遇到「元素定位不准」。本实验**不调用模型、不访问网络、不启动浏览器**，只用 Python 标准库，在一个内置的后台管理页面（筛选表单 + 6 行用户表格 + 新建弹窗）上演示：

1. 从 HTML 抽取链接、按钮、输入框、下拉框，按「角色 + 可访问名称」生成编号快照（平铺版）。名称按 `aria-label` → `<label for>` → 元素文字 → `placeholder` 的顺序取。
2. 给每个元素附上所在区块标题和表格行的首列（带上下文版）。
3. 比较原始 HTML、平铺快照、带上下文快照的字符数，检查只靠名称能否唯一定位。

## 步骤

```bash
python main.py
```

不需要安装第三方包。程序打印快照片段、`METRIC:` 指标、5 项 `[PASS]/[FAIL]` 检查和最后一行 `RESULT:`；任一检查失败时以非零状态退出。

## 预期结果

- 快照体积远小于原始 HTML
- 平铺快照里，每行都有的「编辑」「删除」按钮重名，模型只看名称无法确定点哪一个
- 附上区块标题和行首列（如 `button "删除" @ 用户列表 / 李四`）后，每个元素都能唯一定位

## 局限

- 页面是构造的，样式和脚本的体积由本实验自定，体积比例只说明量级，不代表真实页面
- 用字符数代替 token 数；没有真正让模型根据快照去点击，也没有测通过率
- 真实浏览器的无障碍树还要考虑隐藏元素、Shadow DOM、iframe、动态加载等，本实验的解析器都没有处理
- 「行首列」只适用于首列能区分行的表格；首列重复时需要换成其他能区分的列

## 启示与可以继续尝试

- 写 UI 自动化脚本或给 Agent 做页面工具时，先给它交互元素清单，而不是整页 HTML 或截图
- 页面开发时补齐 `aria-label` 和 `<label for>`，无名按钮（只有图标）对无视觉模型几乎无法定位
- 可以用 Playwright 的无障碍树接口替换本实验的手写解析器，在团队真实页面上跑同样的统计

## 内网复现

- 无第三方依赖，只需要 Python 3，开发机或内网 CI 镜像一般都有
- 程序完全离线运行，不访问网络，不需要 API key、GPU 或浏览器
- 如果改用 Playwright 在真实页面上做，需要通过内网 PyPI 镜像安装 `playwright`，浏览器内核需要从内网制品库下载或提前打进镜像
