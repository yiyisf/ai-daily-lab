# 玩具复现：只看请求就能拦下的越界工具调用

## 目的

Hugging Face 开源的 [safeagents](https://github.com/huggingface/safeagents) 是一个放在 Agent 和模型服务之间的本地代理，在 Agent 执行工具调用之前先检查一遍。它的第一阶段只看请求本身：

- **规则 A**：模型调用了请求里没有声明的工具，直接拦截；
- **规则 B**：工具参数里出现的主机（URL 或裸 IP）在对话里从没出现过，拦截；**模型自己之前说过的话不算数**。

本实验**不是 safeagents 的代码，也不调用模型、不执行任何命令**，只用 Python 标准库按 README 描述的两条规则写一个最小实现，在 6 段手写的模拟会话上运行，帮助理解：

- 这两条规则能拦下哪些常见的越界操作；
- 为什么「模型自己的话不算数」这一条很关键；
- 哪些越界操作不带主机，第一阶段拦不住，需要 safeagents 的第二阶段（atif-scan 规则）或判定模型。

## 步骤

```bash
python main.py
```

程序会逐条打印每个模拟调用的判定（PASS / BLOCK）和原因，然后输出 6 项 `[PASS]/[FAIL]` 检查、`METRIC:` 指标和最后一行 `RESULT:`；任何检查失败时以非零状态退出。

## 预期结果

- 调用未声明的 `shell_exec`、把 `~/.netrc` 发到陌生主机、把代码打包上传到只在模型自己话里出现过的 IP，都被拦截
- 用户消息里给出的文档链接、工具结果（如 README）里出现的镜像地址被放行
- 正常调用没有被误拦
- 读取 `/proc/1/environ` 这类不含主机、用的又是已声明工具的操作，第一阶段放行——这是刻意展示的局限

## 局限

- 模拟会话是手写的，数量很少，拦截率只说明规则逻辑，不代表真实 Agent 流量里的效果
- 主机提取用的是简单正则，真实实现要处理更多写法（编码、拼接、环境变量里的地址等）
- 规则 B 依赖「对话里出现过」：如果攻击者能把恶意地址写进 Agent 会读到的文件或网页（间接提示注入），这条规则就会放行，需要其他手段配合

## 启示与可以继续尝试

- 这两条规则与模型无关、几乎零成本，适合放在自部署模型和命令行 Agent 之间作为第一道关
- 试着在 `SESSIONS` 里加入「恶意地址出现在工具结果里」的会话，观察规则 B 的盲区
- 给 `check_call` 加一条规则（如匹配 `/proc/*/environ`、`--noproxy`），体会 safeagents 第二阶段在补什么

## 内网复现

- 只用 Python 标准库，不需要安装任何依赖，`requirements.txt` 仅作说明
- 程序完全离线运行，不访问网络，也不需要 API key 或 GPU
- 如需试用 safeagents 本身：其安装脚本会联网安装 uv 和 safeagents，内网可先在外网机器下载仓库源码，再通过内网 PyPI 镜像用 `uv sync` 安装依赖；代理只需要能访问你自己的模型服务地址
