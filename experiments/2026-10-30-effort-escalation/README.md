# 玩具模拟：固定最高推理强度 vs 验证失败才升档

## 目的

论文 [What Effort Level Should I Choose?](https://arxiv.org/abs/2610.34491) 指出：默认用最高推理强度成本高，而且不保证每个任务都最好；一个简单的替代做法是**从最低档开始，只有在验证失败后才升档**，在论文测试的模型和基准上都能追平或超过固定最高档。

本实验**不调用任何模型，也不是论文代码**，只用纯 Python 做一个玩具模拟，帮助理解这个策略为什么省钱：

- 题目：随机生成的子集和问题，规模 6、10、14、18 各 60 题，规模越大越难；
- 「推理强度」：随机搜索的采样预算，low / medium / high 分别为 64 / 512 / 4096 次；
- 成本模型：每个档位无论是否提前找到答案，都花掉整份预算（类比思考 token 在开始前就决定了档位）；
- 验证器：只检查答案是否满足约束（类比「跑测试」），不知道标准答案；
- 对比策略：固定 low、固定 medium、固定 high，以及「low → 验证失败 → medium → 验证失败 → high」的升档策略。

## 步骤

```bash
python main.py
```

程序会打印各策略的正确率和平均成本（`METRIC:`）、5 项 `[PASS]/[FAIL]` 检查和最后一行 `RESULT:`；任何检查失败时以非零状态退出。

## 预期结果

- 升档策略的正确率与固定 high 档接近（相差不超过 2 个百分点）
- 升档策略的总成本低于固定 high 档，因为一部分题在 low 档就通过了验证
- 存在三档都能做对的简单题，在这些题上用 high 档纯属多花钱

## 局限

- 玩具模拟的成本结构是人为设定的，节省比例取决于题目难度分布，不能代表真实模型上的数字
- 升档策略的前提是**有可靠的验证器**（测试、类型检查、约束校验等）；没有验证器时无法判断「失败」，这个策略就用不上
- 真实模型里高档位还会改变 Agent 行为（论文提到会更多地自查和搜索），本模拟没有体现

## 启示与可以继续尝试

- 自部署模型支持思考开关或强度档位时，可以在 Agent 外围系统里实现「先低档，测试不过再升档」，而不是全局开最高档
- 调整 `SIZES` 让简单题更多或更少，观察节省比例怎么变化
- 把 `LEVELS` 改成两档或四档，看升档的额外开销何时超过收益
