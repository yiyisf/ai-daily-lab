# 玩具实验：检查待办是否写了验收句、提问是否进了决策文件

## 目的

Tobias Zimmergren 在《Agentic AI engineering: What the humans do, what the agents do, and where the hard lines are》（2026-11-04）里介绍了他管理编码 Agent 的做法，其中几条可以机械检查：

- 每个待办写明阻塞点、依据的决定和「完成」的含义；作者发现写具体的验收句比「做得健壮一点」好用
- Agent 需要人决定的问题只写进一个决策文件，并附上 Agent 的建议
- 决策文件只列待决问题，回答后即删除

本实验**不调用任何模型**，用正则写一个极简检查器，在内置的「好」「坏」两组示例文件上验证它能否区分。本实验约定：验收句用「验收：」开头，建议用「建议：」开头，出现「已回答」视为回答后没有删除。

## 步骤

```bash
python main.py
```

不需要安装第三方包。程序打印坏示例里检出的每条问题、5 项 `[PASS]/[FAIL]` 检查、`METRIC:` 指标和最后一行 `RESULT:`；任一检查失败时以非零状态退出。

## 预期结果

- 好示例零问题
- 坏示例中能检出四类问题：缺验收句、提问写在待办文件里、决策项没有建议、已回答的决策项没删除

## 局限

- 示例是构造的，关键词约定（「验收：」「建议：」）是本实验自定的，原文没有规定具体格式
- 只检查「有没有写」，不判断验收句写得好不好、能不能验证
- 用问号判断「是不是提问」很粗糙，真实文本里会有误报和漏报

## 启示与可以继续尝试

- 把检查器放进 pre-commit 或 CI，Agent 写回的待办和决策文件不合规就让它重写，可以减少「不确定就问我」带来的零散提问
- 可以加一条规则：每个待办必须引用一个决策编号或写「依据：无」
- 规则文件里写明格式约定后，对比 Agent 遵守前后决策文件的长度和人处理所需的时间

## 内网复现

- 无第三方依赖，只需要 Python 3，开发机或内网 CI 镜像一般都有
- 程序完全离线运行，不访问网络，不需要 API key 或 GPU
