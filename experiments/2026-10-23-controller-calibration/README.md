# 排序好不等于建议好：Agent 控制器的校准偏差

## 目的

论文 [Good Judgment, Bad Advice](https://arxiv.org/abs/2610.24649) 在 Terminal-Bench 2.1 上发现：专用决策模型 Jev 1.13 判断「该不该结束」的离线排序（AUROC）优于规则和小模型，但它给出的已完成概率明显偏低，结果让 Agent 做了不必要的验证——成本上升、通过率不变。

本实验用模拟数据演示这一机制：**区分能力（AUROC）和校准是两回事**，按概率阈值去「行动」的控制器，两样都需要。

注意：所有数据由脚本按固定随机种子生成，只演示机制，不复现论文中的任何数字。

## 步骤

1. 模拟 4000 个 Agent run，约 87% 已经完成
2. 两个控制器给出「已完成概率」：
   - A：区分能力强，但概率整体偏低（模拟论文中的专用决策模型）
   - B：区分能力弱，但概率大致校准（模拟简单规则）
3. 统一策略：概率 < 0.5 就让 Agent 再验证一轮，额外成本 0.4（基础尝试为 1.0）；验证不改变结果
4. 计算两者的 AUROC、平均完成概率、不必要验证比例（已完成却被要求验证）和每次尝试的平均成本
5. 用前 200 个带标签的 run 对 A 做简单的分箱保序校准，在其余 run 上重新评估

运行：

```bash
python main.py
```

程序打印 `METRIC:` 指标、`[PASS]/[FAIL]` 检查和最后一行 `RESULT:`，任一检查失败时以非零状态退出。

## 预期结果

- A 的 AUROC 高于 B，但不必要验证比例和每次尝试成本都更高
- 两者通过率相同
- 校准后，A 的不必要验证比例下降一半以上

## 启示与可以继续尝试

- 评估 Agent 的「评审 / 停止 / 验证」组件时，除了 AUROC，还要看校准（例如平均预测概率与真实比例是否接近）和它驱动的实际动作成本
- 可以把阈值、验证成本、真实完成比例换成你自己的数据，观察成本如何变化
- 也可以加入「验证能修复未完成 run」的设定，比较校准前后通过率与成本的权衡

## 内网复现

- **无需任何第三方依赖**，只用 Python 3.8+ 标准库，无需联网，可直接在内网运行
- 把 `main.py` 拷贝到内网机器执行 `python main.py` 即可
- 论文作者的代码在 GitHub（`namanvats/decision-model-controllers`），复现其真实实验需要外网和模型 API，本实验不依赖它
