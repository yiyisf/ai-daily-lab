# 玩具实验：用纯文本检查找出 AGENTS.md 里过期的路径和命令

## 目的

论文 *When Instruction Files Go Stale*（arXiv:2611.09802）研究了 AGENTS.md / CLAUDE.md 里过期的说明：Agent 会照着过期说明去做，事后能绕过失败，但没有一次去修正说明文件。论文选了三类真实的过期说明：测试命令、代码位置、新增组件的流程。

本实验**不调用模型、不访问网络**，只用 Python 标准库，演示一个最小的「说明文件体检」：

1. 在临时目录里构造一个小仓库：按钮组件已从 `src/components/` 挪到 `src/ui/`，测试脚本从 `test:unit` 改名为 `test`，生成组件的 shell 脚本已被 plop 取代。
2. AGENTS.md 仍写着旧的命令和路径。
3. 检查器提取反引号里的 `npm run xxx` 和文件路径，核对 `package.json` 与文件系统，并按文件名、脚本前缀给出候选新位置。

## 步骤

```bash
python main.py
```

不需要安装第三方包。程序打印提取到的引用、判定过期的引用、`METRIC:` 指标、`[PASS]/[FAIL]` 检查和最后一行 `RESULT:`；任一检查失败时以非零状态退出。

## 预期结果

- 三条过期引用全部找出，仍然有效的引用不误报
- 挪走的文件能按文件名找到新位置，改名的脚本能按前缀提示现有脚本
- 换了实现方式的流程（shell 脚本 → plop）给不出候选，只能提示人工确认

## 局限

- 仓库和说明文件是构造的，「过期」的真相由实验自己定义，结果只说明思路可行，不代表真实仓库的检出率
- 只检查反引号里的路径和 npm 脚本；写在普通文字里的路径、Makefile / pnpm / gradle 等命令、「流程」本身是否正确都检查不了
- 按文件名找候选在同名文件多时会给出多个候选，需要人判断

## 启示与可以继续尝试

- 把类似检查放进 CI 或 pre-commit：改目录结构、改脚本名的 PR 顺手更新说明文件
- 论文发现「删掉过期说明」也能避免大部分无效操作：拿不准的说明，宁可删掉
- 可以扩展到 CLAUDE.md、`.cursor/rules`、SKILL.md 里引用的脚本路径

## 内网复现

- 无第三方依赖，只需要 Python 3，开发机或内网 CI 镜像一般都有
- 程序完全离线运行，不访问网络，不需要 API key 或 GPU
- 想在真实仓库上用，把 `build_repo()` 去掉、让 `check()` 指向仓库根目录即可，全程不需要外网
