# 玩具实验：评测集只跑 100 题，BestRand 选题比纯随机稳多少

## 目的

论文 Random Is Almost Enough?（arXiv:2611.00883）指出：用随机抽出的一小部分题目估计模型在全量评测上的分数，多数时候误差很小，但偶尔会出现很大的误差（长尾）。论文提出的 BestRand 保留随机抽样的低成本，用几个「探针模型」的已知分数挑出更有代表性的子集，以减少大误差。

本实验**不调用任何模型**，用 numpy 演示这一流程：

- 用固定种子生成 2000 道题、32 个模型的 0/1 得分矩阵（类 IRT：模型能力、题目难度、区分度，外加题型偏好）
- 前 8 个模型当「探针模型」（假设已经跑过全量），其余 24 个当「目标模型」（只想跑 k 道题）
- `random`：从全量题目里随机抽 k 道
- `bestrand`：按仓库 README 描述的流程，先随机抽 `min(4k, N)` 道题作为候选池，在池内随机抽 128 个大小为 k 的子集，选探针模型平均分向量与池平均最接近（平方 L2 距离）的子集；目标模型的分数只在选题之后使用
- 预算 k = 50 / 100 / 200，每种设置重复 400 个种子，统计目标模型「子集估分 − 全量真实分」的绝对误差（百分点）的平均值、P95、最大值和超过 5 分的占比

## 步骤

```bash
pip install -r requirements.txt
python main.py
```

程序打印对比表、`[PASS]/[FAIL]` 检查、`METRIC:` 指标和最后一行 `RESULT:`；任一检查失败时以非零状态退出。

## 预期结果

- 三种预算下 BestRand 的平均误差和 P95 误差都不高于纯随机
- 预算越大，两种方法的误差都越小
- 实际差距大小以 Actions 的运行输出为准

## 局限

- 得分矩阵是模拟的，真实评测里题目之间的相关性、模型家族差异会让结果不同；论文在 70 多个真实基准上验证，本实验不能替代
- 只实现了 README 描述的选题流程，没有复现论文的误差理论和分布外实验
- 探针模型和目标模型来自同一个模拟分布；论文专门讨论了分数区间、模型家族和时间上的分布偏移

## 启示与可以继续尝试

- 团队给自部署模型选型、做量化或微调回归时，往往只能跑评测集的一部分；可以用已有几个模型的全量结果当探针，先挑子集再跑新模型
- 可以把 `make_matrix()` 换成团队已有的真实评测结果（行是模型、列是题目），看看纯随机的尾部误差有多大
- 可以调整 `N_CANDIDATES` 和 `POOL_MULT`，观察对误差和选题成本的影响

## 内网复现

- 依赖只有 `numpy==2.2.6`，可通过内网 PyPI 镜像安装：`pip install -i <内网镜像地址> -r requirements.txt`
- 程序完全离线运行，不访问网络，不需要 API key 或 GPU
- 如果想试论文官方实现，需要外网访问 GitHub 仓库 George-Ling3/BestRand（MIT 许可），也可以先在外网下载后传到内网
