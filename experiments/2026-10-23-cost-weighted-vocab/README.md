# 按成本而非频次挑选宏 token

## 目的

Dharma-AI 在 Hugging Face 博客 [How Specializing the Vocabulary of SLMs Can Cut Inference Cost by 77%](https://huggingface.co/blog/Dharma-AI/vocabx-vocabulary-specialization) 中介绍了 VocabX：为领域小模型重建词表时，按「省下的钱」而不是「出现频次」挑选新 token，并把重复的多词片段合并成一个「宏 token」。在他们的场景里，省下一个回复（输出）token 的价值是省下一个输入 token 的 7.4 倍。

本实验用一个极简的贪心算法演示：在同样的宏 token 预算下，两种挑法各自压缩了什么、省了多少。

注意：语料是脚本按固定随机种子生成的模拟「作文评分」请求，分词用空格切词近似，不涉及真实模型、真实分词器或 VocabX 的实现；7.4 倍的价格比照搬自原文的案例，只作设定。

## 步骤

1. 生成 300 条请求，每条包含固定的系统提示、随机的作文正文（输入），以及 JSON 格式的评分回复（输出）
2. 在每个字段内统计 2–6 个词的 n-gram，贪心地每次挑一个最优片段合并为宏 token，再重新统计：
   - 按频次：分数 =（片段长度 − 1）× 出现次数
   - 按成本：分数 =（片段长度 − 1）× Σ 各字段出现次数 × 字段单价（输入 1，输出 7.4）
3. 预算分别取 4、8、16 个宏 token，比较 token 减少、加权成本减少和平均回复长度

运行：

```bash
python main.py
```

程序打印 `METRIC:` 指标、`[PASS]/[FAIL]` 检查和最后一行 `RESULT:`，任一检查失败时以非零状态退出。

## 预期结果

- 按频次挑选会先压缩每条请求都重复的系统提示，省下的 token 总数更多
- 按成本挑选会先压缩回复里的 JSON 结构，加权成本降得更多、回复更短
- 预算越紧，两种挑法的成本差距越大

## 局限与可以继续尝试

- 真实部署中系统提示往往能被提示词缓存覆盖，输入侧的实际价格会更低，这会进一步拉大两种挑法的差距
- 原文提醒：把承载决策的内容（如分数）和结构一起合并成一个 token，会损害质量；本实验只算成本，不评估质量
- 可以把 `make_corpus` 换成你自己的请求日志（脱敏后），把单价换成实际的输入 / 输出价格

## 内网复现

- **无需任何第三方依赖**，只用 Python 3.8+ 标准库，无需联网，可直接在内网运行
- 把 `main.py` 拷贝到内网机器执行 `python main.py` 即可
- 若要在真实分词器上尝试类似思路，需要通过内网 PyPI 镜像安装 `tokenizers` 等库，并在内网模型仓库中准备基础模型的分词器文件
