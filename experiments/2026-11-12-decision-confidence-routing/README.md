# 玩具实验：复算 decision model 置信度，按阈值把工单分流到人工

## 目的

Hugging Face 11 月 10 日的文章 *Decision Models in Hugging Face* 介绍了一类不生成文本的模型：输入「状态 + 问题 + 允许的答案」，直接输出每个答案的概率。文章给出了 choice 问题的置信度公式 `(p_max − 1/K) / (1 − 1/K)`（K 为选项数），以及 score 问题按有序刻度求期望值的做法，并附了示例数值。

本实验**不调用模型、不访问网络**，只用 Python 标准库：

1. 用文章示例里的概率复算 choice 置信度和 score 期望值，核对是否与文章给出的数值一致。
2. 用 8 张**构造的**客服工单和构造的概率，演示「置信度高于阈值才自动分派，否则转人工」的分流方式。

## 步骤

```bash
python main.py
```

不需要安装第三方包。程序打印每张工单的预测、置信度和去向，`METRIC:` 指标，`[PASS]/[FAIL]` 检查和最后一行 `RESULT:`；任一检查失败时以非零状态退出。

## 预期结果

- choice 置信度复算为 0.9974000453948975，score 期望值复算为 1.7053890228271484，与文章一致
- 同样的最大概率，选项越多置信度越高，因为公式扣掉了随机猜中的 1/K
- 构造数据上，阈值以上的自动分派准确率不低于「全部自动分派」，低置信度工单留给人工

## 局限

- 第二部分的工单、概率和标注都是构造的，只说明分流思路，不代表真实模型的准确率
- 文章没有给出 score 问题置信度的公式，本实验只复算了期望值
- 阈值 0.6 是随手取的；实际使用要在自己的标注数据上画出「自动分派占比 vs 准确率」曲线再定

## 启示与可以继续尝试

- 分类、路由、打标签这类任务不一定要让模型生成 JSON：拿到概率就能设阈值、转人工，也不会出现格式错误
- 可以用团队自己的工单或需求条目，换成文章里的真实 decision 模型（如通过 Transformers 的 `pipeline("decision", ...)`）跑一遍，再用本脚本的分流逻辑统计
- 置信度阈值可以按部门分别设置，代价高的分类用更高阈值

## 内网复现

- 无第三方依赖，只需要 Python 3，开发机或内网 CI 镜像一般都有
- 程序完全离线运行，不访问网络，不需要 API key 或 GPU
- 如果要接真实 decision 模型：模型权重需从 Hugging Face 下载（需外网，或从内网模型仓库镜像），`transformers` 可通过内网 PyPI 镜像安装；推理本身可离线进行
