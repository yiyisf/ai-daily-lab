# 玩具实验：自动修复只收「检查器确认变好」的改动

## 目的

IBM Research 在介绍 Palette（用小型开源权重模型按指定设计语言生成幻灯片）时，提到一个 check-and-repair harness：每页渲染后由几何检查器找出重叠、截断、越界的文本，交给编辑模型重写，**只有检查器确认这一页变好了才采用重写**，否则保留原样。作者总结的经验之一是「先把检查器做出来」「只接受可测量的改进」。

本实验**不复现 Palette**，也不调用任何模型，只用纯 Python 模拟这条规则的作用：

- 用固定随机种子生成 300 页「幻灯片」，每页 3–6 个文本框，部分故意摆得过大或靠边
- 检查器：越界的框数 + 互相重叠的框对数
- 编辑器：每次随机挑一个框挪动或缩放，可能修好，也可能改坏（模拟不可靠的模型修复）
- 比较三种策略，每页最多修 3 轮：
  - `none`：不修复
  - `blind`：编辑器给什么就收什么
  - `guarded`：只有检查器给出的问题数下降才采用

## 步骤

```bash
python main.py
```

不需要安装第三方包。程序打印三种策略的问题总数、无问题页数、变好页数和变坏页数，然后输出 4 项 `[PASS]/[FAIL]` 检查、`METRIC:` 指标和最后一行 `RESULT:`；任一检查失败时以非零状态退出。

## 预期结果

- `guarded` 不会让任何一页变坏，问题总数低于 `none`，且不高于 `blind`
- `blind` 会把一部分页面改得比原来更糟，说明「修复器」本身不可靠时，没有检查器把关的自动修复可能越修越坏

## 局限

- 「幻灯片」和「编辑器」都是随机构造的，只用来说明「改动要经过检查器验收」这条规则的作用，不代表 Palette 或任何真实模型的修复效果
- 检查器只管几何问题；真实场景里还有内容是否忠实、是否符合设计规范等检查器覆盖不到的问题
- 检查器本身写错时，`guarded` 会稳定地朝错误方向优化

## 启示与可以继续尝试

- 让 Agent 自动修代码、修页面时，把「能自动判定的检查」（测试、lint、组件库使用规则、截图对比）放在采纳之前，而不是事后人工发现
- 对没有视觉能力的模型，几何检查这类确定性规则可以替它「看」页面，例如检查元素是否重叠、是否超出容器
- 可以把 `issues()` 换成团队自己的检查（如「是否使用了组件库以外的按钮组件」），观察同样的规则效果

## 内网复现

- 无第三方依赖，只需要 Python 3，开发机或内网 CI 镜像一般都有
- 程序完全离线运行，不访问网络，不需要 API key 或 GPU
- 如需改成接入内网自部署模型做真实修复，只要把 `editor()` 换成调用内网推理服务的函数即可，其余逻辑不变
