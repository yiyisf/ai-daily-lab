# 玩具实验：用前置策略闸门拦住 MCP 工具路由中的「影子调用」

## 目的

USENIX Security 2026 论文 *ShadowBench-MCP*（arXiv:2611.11720）指出：当编码 Agent 通过 MCP 路由外部工具时，即便用户请求本身不包含恶意意图，只要加上「赶时间」「尽量少调工具」等运行压力（operational pressure），效率优先的路由器就可能选出一条更短但跳过校验、预发、脱敏或审计控制的高风险路径——作者称之为**影子调用（shadow invocation）**。

本实验**不调用模型、不访问网络**，只用 Python 标准库，构造 6 类常见研发与运维工作流（代码合并、配置发布、日志导出、数据库迁移、依赖升级、制品发布），每类包含「常规请求」与「施压变体请求」共 12 条对照样本，对比两种路由策略：

1. **效率优先路由**：当请求带有时间/步骤压力且存在更短路径时，优先选耗时短的快捷工具链。
2. **策略感知前置校验**：在执行前把候选工具链与工作流必需控制集合（`validate`、`staging`、`redact`、`audit` 等）比对，一旦缺失必需安全工具就拒绝快捷路径并回退到合规路径。

## 步骤

```bash
python main.py
```

无需安装第三方包。程序输出每条工作流的路由选择、`METRIC:` 指标、`[PASS]/[FAIL]` 检查项和最终 `RESULT:` 结论；任一检查失败时以非零状态退出。

## 预期结果

- 效率优先路由在 12 条请求中产生 50.0% 的影子调用率（施压变体全部跳过安全工具）
- 启用策略感知前置校验后，影子调用率与安全工具跳过率均降至 0.0%，且 6 条常规请求 100% 正常放行

## 局限

- 本脚本用规则模拟路由决策与控制清单校验，不含真实 LLM 路由器（论文使用 Groq 托管的 `qwen/qwen3-32b` 评测 120 次路由决策）
- 现实场景中工具名和参数可能更隐蔽，需要把控制策略绑定在 MCP 网关层而非仅靠提示词约定

## 启示与可以继续尝试

- 给编码 Agent 接入部署、数据库、日志导出等 MCP 工具时，不要只靠系统提示提醒「别跳过检查」，应在 MCP 网关或 Hook 层强制校验前置工具是否已执行
- 可把本脚本里的 `WORKFLOWS` 替换成团队实际使用的 MCP 工具清单，作为接入新工具前的路由合规自测用例

## 内网复现

- 仅依赖 Python 3 标准库，无任何第三方包，开发机与内网 CI 镜像均可直接运行
- 完全离线运行，不访问外网，不需要 API key 或 GPU
- 若结合内网自部署开源模型（如 Qwen3-32B）做真实路由评测，只需将 `efficiency_first_route` 替换为调用本地 OpenAI 兼容接口并解析工具调用序列即可
