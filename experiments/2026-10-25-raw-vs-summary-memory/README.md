# 保留原文 vs 写入时摘要：Agent 记忆的「证据覆盖率」

## 目的

论文 [Is Complex Agentic Memory Always Needed? Naive RAG Is Stronger Than We Thought](https://huggingface.co/papers/2610.30755)（arXiv:2610.30755）发现：直接对原始对话历史做稠密检索加重排（Raw-RAG），在 7 个基准×模型设置中有 6 个排第一；作者认为保留原始证据比复杂的记忆加工更重要，证据覆盖率高可以抵消利用率低。

本实验用构造的对话历史演示其中的机制：**写入时就做摘要的记忆，会在当时决定保留什么；没保留的信息，之后遇到新问题时无法再找回。** 原文检索的上下文更长，但证据还在。

注意：数据由脚本按固定随机种子构造，检索用的是简单的 BM25（论文用的是稠密检索 + 重排），只演示机制，**不复现论文中的任何数字**。三类问题和两种摘要方式都是本实验的设定，摘要方式的设计决定了它们在某些问题上必然缺证据——这正是要演示的点，而不是对真实记忆系统的评测。

## 步骤

1. 生成约 100 条对话消息：12 个项目的上线日期、负责人、预算被多次修改，修改原因在另一条消息中单独说明，中间穿插无关闲聊
2. 生成三类问题：当前值（latest）、上一次的值（previous）、最近一次修改的原因（reason），并记下每题所需的证据消息
3. 构建三种记忆：
   - 覆盖式摘要：每个（项目, 属性）只存最新值
   - 带历史的摘要：存全部取值，但不存原因
   - Raw-RAG：对原始消息做 BM25 检索，取 top-3 或 top-8 条
4. 统计每种记忆交给阅读模型的上下文是否包含全部所需证据（证据覆盖率），以及上下文长度

运行：

```bash
python main.py
```

程序打印 `METRIC:` 指标、`[PASS]/[FAIL]` 检查和最后一行 `RESULT:`，任一检查失败时以非零状态退出。

## 预期结果

- 覆盖式摘要能回答全部「当前值」问题，但「上一次的值」和「原因」问题全部缺证据
- 带历史的摘要补上了旧值，但仍缺「原因」
- Raw-RAG 的覆盖率随检索条数增加而上升，代价是上下文长了一个数量级

## 启示与可以继续尝试

- 摘要式记忆不是错，而是「提前做了取舍」：如果你的 Agent 只会被问当前状态，它又省又准；如果用户会追问历史和原因，就要保留原文或至少保留指向原文的链接
- 把 `Raw-RAG top-k` 的 k 改成 1、2，观察覆盖率如何下降——检索条数太少时原文检索也会漏
- 增加更多同名项目的干扰消息，观察 BM25 的覆盖率变化；论文用重排模型来缓解这类问题
- 本实验只看「证据在不在上下文里」，不看阅读模型能否用好它；论文也指出覆盖率和利用率是两件事

## 内网复现

- **无需任何第三方依赖**，只用 Python 3.8+ 标准库，无需联网，可直接在内网运行
- 把 `main.py` 拷贝到内网机器执行 `python main.py` 即可
- 如要换成论文中的稠密检索 + 重排，需要嵌入模型和重排模型；论文附录给出了 Qwen3-Embedding-4B 和 Qwen3-Reranker-4B 的开源替代组合，权重可通过内网的 Hugging Face 镜像下载，本实验不依赖这些
