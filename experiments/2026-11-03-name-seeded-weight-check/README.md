# 玩具实验：按张量名重新生成，识别伪造的模型权重

## 目的

11 月 1 日，Hugging Face 上一个 7.72 TB 的仓库被当作「Anthropic 下一代 Mythos 级模型的训练中检查点」传播。CellCog 和 Hugging Face 社区用户核查后发现：每个张量都能由张量名重新生成——对名字做 SHA-256，作为 NumPy PCG64 的种子，生成正态分布值，缩放后舍入到 bfloat16。也就是说，这份权重根本没训练过。

本实验**不下载、不复现那个仓库**，只用 NumPy 在本地构造三组小型「检查点」，演示这种核查方法：

1. 用同一配方伪造的权重
2. 模拟训练过的权重（norm 权重围绕 1、矩阵带低秩结构）
3. 换了一种哈希（MD5）伪造的权重

对每个张量按名字重新生成一份（缩放取 1），比较两者符号一致的比例。符号比较与缩放系数无关，所以不需要知道原配方的缩放值。

> 原文没有给出「哈希摘要如何转换成种子」的具体细节，本实验假设取摘要前 8 字节（小端）。这只影响演示用的配方，不影响方法本身。

## 步骤

```bash
pip install -r requirements.txt
python main.py
```

程序打印每个张量的符号一致率，然后输出 4 项 `[PASS]/[FAIL]` 检查、`METRIC:` 指标和最后一行 `RESULT:`；任一检查失败时以非零状态退出。

## 预期结果

- 同配方伪造的张量符号一致率为 100%，即使舍入到 bfloat16 也不受影响
- 模拟训练权重和换了哈希的伪造权重都在 50% 左右（与随机猜一样），不会被判为伪造
- 伪造的 norm 权重均值接近 0，而训练过的 RMSNorm 权重通常围绕 1，可作为辅助线索

## 局限

- 所有张量都是本地构造的小矩阵，不代表任何真实模型
- 这种检查**只能证伪，不能证真**：伪造者换个种子或配方，检查就查不出来；一份权重是不是某厂商的，最终要看厂商的一手确认
- 「norm 权重围绕 1」只是常见情况，有的架构会用别的初始化或参数化，不能单独作为判断依据

## 启示与可以继续尝试

- 下载来路不明的大权重前，先用 HTTP Range 请求读 safetensors 文件头，抽几个小张量（尤其是 norm 和卷积核）看分布
- 不要运行匿名仓库里的自定义代码（如 `trust_remote_code`）
- 团队内网模型仓库收录新权重时，可以把「来源是否为官方组织账号」「是否有厂商公告」列为必查项

## 内网复现

- 依赖只有 `numpy`，可通过内网 PyPI 镜像安装：`pip install -i <内网镜像地址> -r requirements.txt`
- 程序完全离线运行，不访问网络，不需要 API key 或 GPU
- 如果要对真实的 safetensors 文件做同样的检查，可用内网安装的 `safetensors` 库按张量名读取后调用 `sign_match`；不要为此去下载可疑仓库的完整权重
